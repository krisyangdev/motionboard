# Chat Animation

The camera sits close on a chat panel: a prompt is typed into the composer and sent, the bubble springs up, the AI shows Thinking… and runs three tool-call cards that spin and tick off, the reply streams in word by word, and the camera pulls back as a blank preview beside the chat fills with an invoicing dashboard before the Mosaic lockup.

## How to use this recipe

You are a coding agent. The user wants this shot for their own product. Follow these steps.

1. **Know the product.** If the product is clear from the user's repo or conversation, ask nothing and start. Otherwise ask once for: product name, logo file, brand colors.
2. **Pick the output.** If the user's message says a video or their website, do that. Otherwise ask once which one they want.
   - **Video (HyperFrames).** Copy the folder `../source/chat-thread/` (next to this file in the skill) into the user's working folder, for example `cp -R <skill dir>/source/chat-thread ./chat-thread`. Adapt `index.html` (see "What to adapt"). Run `npx --yes hyperframes@0.8.209 check` on the untouched copy first and note its result. Preview with `npx --yes hyperframes@0.8.209 preview`, render an MP4 with `npx --yes hyperframes@0.8.209 render` (into `renders/`, named with a timestamp). The same commands are in `package.json` as `dev`, `check`, `render`; pass flags after `--`, as in `npm run render -- --quality draft`. Rendering needs network access for web fonts and GSAP.
   - **Website motion.** Port the GSAP timeline in `index.html` into the user's site, using their stack (React, Vue, Svelte, plain HTML). Build the same DOM structure, keep the timeline's durations, delays and easings exactly, and start it when the element scrolls into view (IntersectionObserver or ScrollTrigger). Respect `prefers-reduced-motion: reduce`: show the final frame as a static state and skip the movement.
3. **What to adapt.**
   - **Brand layer** (product name, logo, colors, fonts, copy): replace directly with the user's.
   - **UI layer** (the product screens, cards, windows, controls shown in the shot): rebuild the user's real UI as clean DOM, from their codebase (components, design tokens) or from a screenshot used as reference only. Never paste a screenshot into the shot.
   - **Motion** (timing, easing, camera moves, layering, stagger, order of events): keep exactly as in the source. This is what the recipe is.
   - The timeline targets UI elements by id and class, and camera moves land on fixed coordinates. Keep the ids the timeline uses, keep row counts and text lengths close to the source, and when the layout moves, update the target coordinates without changing the times.
4. **Fonts.** HyperFrames fetches Google Fonts such as Inter on its own. Some sources use macOS local fonts (PingFang, Songti via `local()`). Use the user's brand font when it can be bundled; for a system font such as SF Pro, use Inter. Check that text still fits its boxes.
5. **Verify.** Compare the render with the preview film on the recipe page at the beat times in the Timing row. The beats, timing and camera should match; only brand and UI content differ.

## Matches requests like

- A sentence is typed into the composer and the bubble springs into the thread when it is sent

## Why it works

The camera starts tight on the chat panel and stays on it, moving through it, for the first 5.9s. The 21px interface text is scaled 1.75–1.85x to about 37–39px, so the prompt, the bubble and the tool-card titles all read. The preview beside it is just a dotted grid and Nothing to preview yet during that time, so the eye has one place to go. Things happen in cause-and-effect order with room between them: typing takes 1.25s, the bubble springs up on send, Thinking… holds for 1.15s, and the three tool cards appear 0.65–0.7s apart and each spins for 0.52–0.62s before it ticks, so every step can be read. On the same frame the last card ticks (5.95s) the preview swaps to the dashboard, the reply starts streaming 0.05s later, and the camera pulls back over 1.15s from 5.9s, so the chat and its result share one frame and the viewer reads this sentence made this app. The dashboard builds in parts: title, stat cards, chart and list come in one after another, the numbers count and the bars rise one by one, so something is moving in the frame through the pull-back until 7.8s. Specific tool-card titles and subtitles (a file name, line count, column count, component count) make the AI's steps believable. The light background has one accent, purple: the bubble, the send button, the ticks and the Nov bar are all the same purple, and the pink in the progress bar and the streaming words appears only on things that are being generated.

## Often confused with

- [Typing Animation (Typewriter Effect)](./typing-animation.md): Rhythmic Typing is monospace characters and a caret on a dark background and covers only the typing; here the typing sits in a real composer and is followed by a bubble, thinking, tool steps and an app that builds at the same time.
- [Zoom-to-Cursor Effect](./zoom-to-cursor.md): Zoom to Cursor pushes in fast for one click or input and pulls back; here the camera follows the chat slowly down through four stages (typing, thinking, tool steps, reply) and pulls back once, when the result appears.
