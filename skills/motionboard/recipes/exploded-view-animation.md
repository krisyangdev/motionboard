# Exploded View Animation

A phone's cover glass, display, frame, logic board, battery, wireless coil and back glass separate in the air one by one while three callouts name the glass, the chip and the battery. The top three layers fade, the camera dives into the board and pulls out, and the seven layers close from the back up into the whole phone beside the Arden One lockup.

## How to use this recipe

You are a coding agent. The user wants this shot for their own product. Follow these steps.

1. **Know the product.** If the product is clear from the user's repo or conversation, ask nothing and start. Otherwise ask once for: product name, logo file, brand colors.
2. **Pick the output.** If the user's message says a video or their website, do that. Otherwise ask once which one they want.
   - **Video (HyperFrames).** Copy the folder `../source/exploded-view/` (next to this file in the skill) into the user's working folder, for example `cp -R <skill dir>/source/exploded-view ./exploded-view`. Adapt `index.html` (see "What to adapt"). Run `npx --yes hyperframes@0.8.209 check` on the untouched copy first and note its result. Preview with `npx --yes hyperframes@0.8.209 preview`, render an MP4 with `npx --yes hyperframes@0.8.209 render` (into `renders/`, named with a timestamp). The same commands are in `package.json` as `dev`, `check`, `render`; pass flags after `--`, as in `npm run render -- --quality draft`. Rendering needs network access for web fonts and GSAP.
   - **Website motion.** Port the GSAP timeline in `index.html` into the user's site, using their stack (React, Vue, Svelte, plain HTML). Build the same DOM structure, keep the timeline's durations, delays and easings exactly, and start it when the element scrolls into view (IntersectionObserver or ScrollTrigger). Respect `prefers-reduced-motion: reduce`: show the final frame as a static state and skip the movement.
3. **What to adapt.**
   - **Brand layer** (product name, logo, colors, fonts, copy): replace directly with the user's.
   - **UI layer** (the product screens, cards, windows, controls shown in the shot): rebuild the user's real UI as clean DOM, from their codebase (components, design tokens) or from a screenshot used as reference only. Never paste a screenshot into the shot.
   - **Motion** (timing, easing, camera moves, layering, stagger, order of events): keep exactly as in the source. This is what the recipe is.
   - The timeline targets UI elements by id and class, and camera moves land on fixed coordinates. Keep the ids the timeline uses, keep row counts and text lengths close to the source, and when the layout moves, update the target coordinates without changing the times.
4. **Fonts.** HyperFrames fetches Google Fonts such as Inter on its own. Some sources use macOS local fonts (PingFang, Songti via `local()`). Use the user's brand font when it can be bundled; for a system font such as SF Pro, use Inter. Check that text still fits its boxes.
5. **Verify.** Compare the render with the preview film on the recipe page at the beat times in the Timing row. The beats, timing and camera should match; only brand and UI content differ.

## Why it works

The seven layers share one axis with identical x and y and are spaced only on z, so the viewer reads one phone lifting apart and settling back together. They do not move as a block: the separation starts are staggered across 1.0–1.32s and each layer eases with expo.out over 1.7s, fast first and slow at the end; closing runs in the reverse order, back glass first and cover glass last, with a 1.05s cubic in-out, a different rhythm from the separation, so it reads as assembly. The camera tilts to 72° while the layers separate so the gaps between them show; to see the board, the cover glass, display and frame first fade and rise 100px and only then does the camera dive in, so nothing above the board blocks it. Callouts arrive one at a time, 0.3s apart, and each leader end is re-projected every frame to its part's current position, so it stays attached while the part rises; the callout text matches what is printed on the parts (A1 · 3NM · 8-CORE on the chip lid, 3,890 mAh on the battery label). The callouts fade 4.1–4.5s and the cover glass waits until 4.35s to rise. Every layer is drawn with edge thickness and real detail (traces, chips and raised packages on the board, a label and orange pull tabs on the battery, copper on the coil), so the close-up on the board holds up. There is one accent color, amber #f5b04a.

## Often confused with

- [X-Ray Effect](./x-ray-effect.md): X-ray Dissolve cross-dissolves the inner structure into the outer shell from one camera position and the parts never leave their place; Exploded View Animation pulls the parts apart along one axis so each layer shows on its own, then puts them back together.
- [Macro Pull-out Reveal](./macro-pull-out-reveal.md): Macro Pull-out Reveal stays at extreme close range and ends on one pull-back to the whole device; here the device itself splits into seven layers, the camera dives into the board and pulls out, and the layers then close.
