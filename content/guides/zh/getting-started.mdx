我们的每个站点都从同一个模板开始，所以新建一个站点只需要几分钟。这篇指南覆盖第一个小时要做的事：创建仓库、改成自己的站点、上线。

## 开始之前

你需要 Node 22、npm 和 Git。要发布站点，还需要一个 Cloudflare 账号，因为站点由一个 Cloudflare Worker 提供服务。除此之外不用安装别的东西：数据库、队列和支付部分在你正式启用之前都使用模拟服务。

## 克隆模板

把模板复制到新文件夹并安装依赖。

```bash
git clone https://github.com/krisyangdev/site-template.git my-site
cd my-site
npm install
```

## 修改站点配置

打开 `site.config.ts`。这个文件集中了站点专属的全部内容：名称、域名、语言、默认标题和描述、联系邮箱以及统计设置。改完这些值，共享代码不需要再动。

先把示例内容当作参照：每种页面的写法都能在示例文件里找到。然后替换示例内容。工具页放在 `content/tools/`，指南放在 `content/guides/`，法律页面放在 `content/legal/`。站点自己的代码放在 `src/site/`。

<Evidence caption="每种页面在仓库里的位置，以及它得到的网址。">

| 页面 | 源文件 | 网址 |
| --- | --- | --- |
| 工具 | `content/tools/word-counter.json` | `/tools/word-counter/` |
| 指南 | `content/guides/zh/case-converter.mdx` | `/zh/guides/case-converter/` |
| 汇总页 | `content/hubs/tools.json` | `/zh/tools/` |
| 关于 | `content/about/zh/about.mdx` | `/zh/about/` |
| 隐私 | `content/legal/zh/privacy.mdx` | `/zh/privacy/` |

</Evidence>

只有某种语言有自己的文件或文字块时，页面才会在这种语言里出现。给工具加一个中文文字块，或者在 `content/guides/zh/` 下放一个文件，页面就会出现在 `/zh/` 下。不写就没有这个页面，所以搜索结果里不会出现翻译不全的内容。

## 添加第一个页面

建议一次只加一个页面，加完就运行 `npm run seo-report`，确认它被收录而不是被挡在索引之外，再继续加下一个。这样出了问题，原因一定就在刚加的那个页面里，不用在一堆新内容里反复排查。

把 `content/tools/word-counter.json` 复制成一个新文件，修改 slug 和文字，并让 `tool` 字段指向你在 `src/site/tools/` 里写的组件。每个页面都要在 `keyword` 里写明它对准的搜索词，在 `demand` 里写明你是在哪里核对这个词的需求的。标题和第一段围绕这个词来写，因为访客就是搜了这个词才来到页面的。

页面要如实说明自己能做什么。只讲怎样在别处完成某件事的页面是指南，不是工具，构建时对两者的要求不同：工具需要有能用的组件、三到四个步骤、一个示例和至少四个问答；指南需要足够的篇幅、几处指向你的工具的链接，以及一份一手的证据，例如表格或截图。

## 持续合并模板更新

把模板添加为第二个远程仓库。模板有改进时，直接合并，不用手动复制文件。

```bash
git remote rename origin template
git remote add origin git@github.com:you/my-site.git
git fetch template
git merge template/main
```

共享代码在 `src/core/` 和 `scripts/` 里。你的改动只放在 `src/site/`、`content/` 和 `site.config.ts`，合并就不会产生冲突。

## 运行、测试、构建、部署

启动开发服务器，检查成果，然后发布。

```bash
npm run dev       # 本地服务器，支持热更新
npm test          # 单元测试和内容检查
npm run build     # 把每个页面预渲染成静态 HTML
npm run deploy    # 构建并发布到 Cloudflare
```

## 发布并验证

第一次部署之后，打开线上地址检查三件事：首页在手机上加载是否够快，语言切换是否会跳到另一种语言里的同一个页面，以及 `/sitemap.xml` 里是否列出了你预期的页面。在 Search Console 和 Bing 站长工具里提交一次站点地图，之后的变化它们会自己跟进。

## 检查搜索引擎会看到什么

添加页面之后运行 `npm run seo-report`。它会按页面类型列出有多少页面可以被收录，以及某个页面为什么被挡在索引之外，例如指南不足 1100 个字，或者工具页没有演示示例。按它列出的原因修改，再运行一次 `npm test`。

上线后，可以看看[工具页](/tools/)了解成品页面的样子，用[字数统计](/tools/word-counter/)看一个能用的工具是什么样，再读[大小写转换](/guides/case-converter/)看一篇教程的写法。[关于](/about/)页面展示了每个站点都需要的说明。
